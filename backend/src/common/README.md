# Response & error standard

The response contract every API follows. The full conventions live in `.claude/rules/api-design.md` and
`.claude/rules/errors.md`.

## Success envelope

```typescript
{ status: 'success', message: string, data: T, meta?: {...} } // meta only on lists
```

- `ResponseInterceptor` (global) wraps whatever a handler returns in a `SuccessEnvelope`, unless it already is one.
  Only instances of the class count as envelopes, so data that happens to have `status` and `message` keys is
  still wrapped.
- `ResponseHelper` builds envelopes when the message matters:

```typescript
ResponseHelper.success(data, 'Article created');
ResponseHelper.paginated(items, total, page, limit, 'Articles retrieved'); // meta: page, limit, total, totalPages
ResponseHelper.cursorPaginated(items, meta, 'Entries retrieved'); // meta: limit, nextCursor, hasMore
```

- There is no helper for errors: errors are always **thrown**, so `GlobalExceptionFilter` answers with the right
  HTTP status.

## Error envelope

```json
{
  "status": "error",
  "message": "Email is already registered",
  "data": null,
  "error": {
    "code": 409,
    "errorCode": "USER_EMAIL_TAKEN",
    "details": null,
    "requestId": "7f1c2d3e-4b5a-4c6d-8e7f-9a0b1c2d3e4f",
    "path": "/v1/users",
    "timestamp": "2026-01-01T00:00:00.000Z"
  }
}
```

- `errorCode`: stable code for clients to branch on (never on `message`). Generic codes are in
  `constants/error-codes.ts`; an exception without one gets the code of its HTTP status.
- Validation failures → 400 `VALIDATION_FAILED`, `details = [{ field, message }]` (nested fields as `items.0.name`).
- Prisma errors are mapped in one place: P2002 → 409 `CONFLICT` (with `details.fields`), P2025 → 404,
  P2003/P2034 → 409.
- Unexpected errors → 500 `INTERNAL_ERROR` with a generic message; the stack is logged, never returned.

Throwing:

```typescript
throw new ConflictException({
  errorCode: 'USER_EMAIL_TAKEN',
  message: 'Email is already registered',
});
```

## Request ID

- Every response carries an `X-Request-Id` header, always generated by the server (a client-sent id is ignored).
- The id is in `error.requestId`, and `AppLogger` appends it to every log line of the request (`[req <id>]`), so an
  error response leads straight to its logs.
- Read it anywhere with `RequestContext.requestId()`.

## List query

`query/` holds the list contract:

- `ListQueryDto` (offset: page, limit ≤ 100, sort, search, fields, include) with `pageMeta` — used by the
  new-resource template (`.claude/skills/new-resource/reference/templates.md`).
- `CursorListQueryDto` (cursor, limit, sort, search, fields, include) with the keyset helpers `parseCursorSort`,
  `cursorWhere`, `cursorOrderBy`, `cursorSelect`, `cursorPage` — used by `AuditService.list`. The cursor carries
  its sort and the last row's sort value and id; clients send it back unchanged with the same sort and filters.
- `ProjectionQueryDto` for detail endpoints, and the whitelist helpers `parseSort`, `buildSelect`, `buildSearch`.
